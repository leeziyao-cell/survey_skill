# Survey 写作 Skills

一套在实际 Survey 写作中持续调整的中文学术写作 skills，覆盖章节结构设计、段落蓝图与正文撰写、已有正文精修。

这些规则与范例来自具身决策 Survey 的写作实践。使用时需要提供自己项目的目标、材料和反馈，逐步调整适合自己的论证方式与表达习惯。

## 选择合适的 skill

| Skill | 适合的任务 | 主要输入 |
| --- | --- | --- |
| [design-survey-chapter](skills/design-survey-chapter/SKILL.md) | 判断章节职责、组织主轴、分类依据，以及与相邻章节的分工 | 论文目标、现有目录、文献证据和当前结构问题 |
| [survey_bluewrite](skills/survey_bluewrite/SKILL.md) | 根据结构与文献设计段落蓝图，撰写或扩改正文、比较、挑战和图注 | 给定结构、可靠文献材料，以及需要完成的范围 |
| [survey_refine](skills/survey_refine/SKILL.md) | 精修已有中文正文，改善解释、例证衔接、比较与语言表达 | 现有正文、必要上下文和修改约束 |

三者可以按“结构设计 → 蓝图与成文 → 正文精修”的顺序使用，也可以只调用当前需要的一项。有了结构和文献即可直接规划蓝图，有了正文即可直接精修。

## 调用示例

**章节结构设计**

```text
请使用 $design-survey-chapter，根据我提供的论文目标、目录和文献证据，
判断本章各节是否分别回答了独立问题，并指出需要调整的边界。
先给结构建议，不修改正文。
```

**蓝图与正文**

```text
请使用 $survey_bluewrite，根据以下小节结构和已核查的文献材料设计段落蓝图。
说明每段要解释什么、比较哪些做法、文献分别支持什么，以及怎样接到下一段。
本轮只交付蓝图。
```

**已有正文精修**

```text
请使用 $survey_refine，精修下面的中文 Survey 正文。
保留现有标题、引用键和证据边界，讲清观点、连接例子，删除重复收束。
在一个 latex 代码块中交付完整修订稿。
```

## 安装到 Codex 项目

克隆本仓库：

```bash
git clone https://github.com/leeziyao-cell/survey_skill.git
```

将 `skills/` 下的三个完整文件夹放入目标项目的 `.agents/skills/`，保留 `references/` 和已有的 `agents/`。三个 skill 应处于同一目录层级，使章节设计与蓝图写作之间的相对链接继续有效。安装后在新的 Codex 会话中调用对应名称。

如果希望直接维护仓库中的版本，可以在目标项目的 `.agents/skills/` 中建立指向这三个目录的软链接。这样项目读取的就是仓库中的同一份文件，无需反复复制。

## 材料与使用边界

- 文献事实、本文分类与作者综合判断需要区分。具体事实与引用由当前任务的可靠文献支持。
- `references/` 保存结构判断方法、蓝图证据规则、历史讨论和认可的正文范例。学习其论证与表达方式，不直接迁移例子的技术结论、分类或段数。
- 范例中的 Ch3、Ch4、WM 等名称及历史文件路径属于原写作项目的背景。使用本仓库不要求具有相同章节或文件，也不需要安装 Knows。
- 范例中的 LaTeX 引用键来自原写作任务；本仓库未附完整论文或 BibTeX 库。这些范例用于阅读和学习写法，不作为独立可编译论文模板。
- 涉及章节结构、文献范围或主要学术判断的调整，按作者当次授权执行。

## 修改与同步

建议只维护一份正式版本。修改仓库中的 skill 后，检查改动并提交到 GitHub：

```bash
git diff
git add skills/ README.md .gitignore
git commit -m "改进正文精修的段落衔接规则"
git push
```

本地修改不会自动上传。可以积累一轮经过实际使用验证的调整后再提交；如果使用的是复制安装的版本，需要先将修改同步回仓库目录。
