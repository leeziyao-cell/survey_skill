# Survey 正文精修

将用户提供的章节初稿改成连贯、清楚、可直接复制的学术正文。重点让读者看懂每段解释什么、为什么比较这些文献、方法究竟哪里不同，以及各段怎样共同回答本节问题。默认在对话中用 `latex` 代码块交付修订稿。

在事实与证据准确的前提下，先保证解释充分、例子承接自然，再压缩表达。删去重复介绍、无关细节和空泛总结，保留理解观点及比较所需的过程、原因和后果。精修可以补足解释，不能只靠缩短句子、减少段数或补齐首尾句完成。

本会话首次精修文献论述正文时，先读[作者认可的完整正文与三项标注](references/approved-wm-prediction-section.md)，参照其解释深度和例证连接方式。已读则复用，不增加作者验收样段、重读整篇参考论文或另交校准报告的前置步骤。

## 精修前的适用性判断

先判断当前问题主要发生在章节职责、段落组织还是句子表达，再决定修改范围。先保证事实与证据准确、内容有独立作用，再处理段落安排和表达形式。保留既有结构是默认修改范围，不表示既有结构已经合理。

- 在内部确认当前段落或小节回答什么问题，相比相关前文新增了什么事实、比较或综合判断，以及证据是否足以支持这些内容。不要只为现有顺序补出一条说得通的故事线。
- 检查范围随任务而定。局部润色只读必要上下文。整节精修利用已有正文，定向对照最相关的小节，检查职责是否重叠。优先采用用户指定稿件和最新正文，蓝图与历史讨论只作辅助。上下文不足时说明判断范围，不声称已经排除全章重复。
- 同一论文跨段或跨节出现不自动构成重复。重点检查是否在回答同一问题、复述同一机制或结果，却没有增加新的分析。介绍怎样评价与检验评价是否可信可以形成承接，是否分节仍取决于各节是否有独立论证任务。
- 没有实质冲突时直接精修，不输出检查报告，不重新开展整套写作校准、全章审查或文献检索。检查步骤不单独建文件，也不要求作者先验收样段。
- 发现实质冲突时，简短说明具体重叠或缺口、依据位置，以及对本轮修改的影响。不要为了维持原结构而掩盖问题。冲突局部可隔离时，继续完成不受影响的精修；若冲突使整节精修失去意义，先提出最小调整建议，不将原结构润色后声称问题已解决。
- 用户要求保持标题、段数或篇幅时，仍应指出影响论证的问题。未经授权不调整章节、taxonomy 或主要结论；本轮已有相应授权时直接执行，不重复请求确认。

## 范围与材料

- 在结构足以支持本轮精修时，用户给出整章初稿就完成所给整章，不只改开头几段或只交修改建议。默认保留现有标题层级、主要论点、taxonomy、文献范围和必要证据；实质冲突按前述适用性判断处理。只有 outline 时不自行扩写整章。
- `%` 等标记中的作者批注用于指导修订，不原样留在正文。先判断批注针对表达、事实还是学术判断，再修正真正的问题。不能为了满足措辞要求改变文献事实。
- 默认只在对话交付，不修改正文文件、BibTeX 或章节蓝图。用户明确要求改文件时再按其范围修改。普通精修直接执行；需要超出当前授权改变主分类、章节边界或主要结论时，先说明具体缺口并取得作者确认。
- 优先使用初稿、已有核查、文献原文及项目 BibTeX。普通表达修改不重新开展文献调研。新增方法能力、实验细节或因果判断前定向核查，不凭印象补全。
- 与一般蓝图设计、初次正文撰写区分。本 skill 专注已有正文的精修，不要求先交蓝图、比较表或审计报告。
- 直接把初稿精修为指定范围的完整正文，主动补足在证据范围内的解释和承接。若用户给的是写作蓝图并要求成文，使用 `survey_bluewrite` 完成正文生成，并按本 skill 的三项标准内部复读；不把重新设计蓝图或多轮磨样段作为默认要求。只有短提纲且缺乏证据时，仍按既有范围与证据边界处理。

## 先确定论证关系

确认内容有必要保留后，先明确本段要让读者获得什么认识，再判断各段之间怎样承接、比较或递进。仅能概括出讨论主题或论文名单时，需要在现有证据中重新梳理中心意思及其解释，不能只补主题句、连接句和总结句。定义、导入和流程说明按其实际用途检查，不强求每段都有独立结论。不把内部分析写进论文，也不另存流程文件。

### 并行段

几项工作共同回答一个问题，分别提供不同做法或支持同一判断。先写清共同问题与比较依据，再选择能说明差别的机制细节。各例尽量回答相同的问题，不能一篇讲输入、一篇讲网络、另一篇讲结果，却不说明这些信息怎样构成比较。

用具体差别连接例子，例如按什么单位保存信息、动作何时进入训练、后续预测使用什么输入。同一路线的多篇文献可以合并支撑一句话，不必逐篇介绍。时间先后或“进一步”不自动构成递进关系。

### 串行段

后面的内容接住前面已经交代的问题、条件或代价。例如已有做法怎样工作、遇到什么困难、直接处理带来什么代价、另一种办法怎样应对。每一步都要写出承接的具体内容，不能只用“随后”“进一步”串论文。

区分论证递进、历史影响和系统执行顺序。按同一问题组织文献，不等于后文方法直接受前文启发。只有证据支持，才能写“基于某项工作”“为改进该方法”。讨论模块执行先后时，要写清后一个模块怎样使用前一个模块的输出。

### 混合关系与分类边界

允许主线递进、局部例子并列，也允许并行段内存在某条路线的演变。不强行把整段归入单一形式。按不同问题展开的比较维度不能无说明地混列为互斥方法类别。例如生成单位与训练输入回答不同问题，转向后者时应说明前者为何还不足以解释预测表现。

## 段首、例子与段尾

### 段首先承接前文，再引出新问题

- 新段落和新章节先承接前文已经建立的对象、过程、结论或尚未解决的问题，再自然引出新的比较与判断。章节开头也要说明讨论为何从上一章节推进到这里，不直接跳到当前论证观点，不用“本段讨论”“本小节介绍”代替内容上的联系。
- 衔接只依据已提供的前文。没有相邻内容时，从当前材料中已有的背景或问题引入，不虚构上一段讲过什么，也不强接无关内容。
- 将抽象名称还原成过程。例如，将“动作条件的学习”具体写为模型需要学习执行不同动作后状态怎样变化。
- 直接写具体问题，不用“对于前一个问题”“对于后一个问题”“下面分别介绍”。观点句后进一步解释其具体含义、成立原因或实际影响，让读者理解本段为什么讨论这些方法。解释要展开具体过程，不能换词重述观点或把论文介绍当作解释。相邻文字已讲清时，保留有效解释，不机械添句。
- 在观点或解释之后，用连接句说明接下来的例子回答哪个具体问题、补充什么或形成什么对照。读者在看到方法名称之前，或读完例子开头时，应能知道为何介绍它。连接可独立成句或融入例子开头；仅加“例如”“此外”“另一方面”不能建立联系，也不能把并列方法改写成技术必然演进。

### 按文献的论证作用决定篇幅

- 先判断文献在当前论述中承担什么作用。仅支持一个观点时，可用观点加引用；比较机制时，解释形成差别的过程；用于限定结论时，保留必要的实验条件和结果。无需把每篇文献都展开成完整的方法介绍。
- 需要解释机制时，用足够篇幅讲清与本段中心意思有关的做法、用途和结果，以及它们怎样支持当前判断。详略以读者理解为准，不按每篇一到两句压缩必要解释，也不为凑句数机械拆句。机制或结果已经把道理讲清时，不再另加重复解释。
- 删去不服务当前论点的模块、训练标签、内部迭代和实验配置，保留改变事实成立条件的限定。内容转向另一项独立意思或因果步骤过多时再拆句，也不把多项独立意思挤成逗号堆砌的超长句。
- 不突然转向另一个分析层次。比较状态组织时，若网络名称不能帮助理解组织方式，直接解释对象信息怎样参与预测即可。重要术语第一次出现时先说明它做什么。
- 每个例子应支持主题句，并与相邻例子围绕同一问题形成比较或承接。出现任务对象、粒度或训练阶段变化时，说明这个变化为什么值得讨论，不靠论文名称维持段落。
- 机制比较涉及模型参与决策时，写清模型预测或生成什么、输出交给谁、怎样改变后续动作或判断。不能只介绍评价器或规划器的操作，让当前小节讨论的模型作用缺席。仅作观点证据的引用无需重述完整调用过程。
- 数据集、基准或工具首次出现时，至少让读者知道其在这里承担什么作用，例如训练记录或评测数据。仅作来源时使用名称、最少必要的角色说明及已有引用，不扩写无关背景。保留实验结果时，要说明测量对象和必要条件。
- 不能因只有一篇引用就机械删除证据，也不能把一项特殊设置写成整个领域的普遍规律。证据范围与本段主张不匹配时，保留局部结论、缩小主张或移去偏离主线的分支。重要内容的删除或移动应在代码块外简短说明，不用新增空泛结论补位。

### 引用紧贴证据，避免重复装饰

介绍具体方法时，通常采用“方法名~\cite{key} + 具体机制或结果”的形式；文献用于支持观点时，采用“观点句 + 引用”，不必逐篇点名。引用紧贴其支持的事实，不把方法名与唯一引用隔开几个独立陈述，也不在同一例子的介绍、结果和限制处反复装饰同一引用。

同一事实或机制尽量集中介绍。某篇文献支持不同论点时，可以在对应位置引用，但不重复展开同一内容。不得仅为减少引用次数，把事实移入不服务其主题的段落。换用其他例子前，先判断现有文献是否已经足以支撑论点，不为维持每段固定的例子数量而新增论文。

重复引用不构成独立证据。保留原有 `\cite{}` 键，不猜造新键。需要补数据集引用时先查现有 BibTeX，确实缺失则核查来源并在代码块外说明，不交付虚构键。

### 根据论述是否完成选择总分或总分总

文献密集的论述段围绕中心意思展开必要解释，让例证、比较和综合形成连贯论述。解释和例子已把观点讲清时，总分结构即可结束。例子之后还能比较不同做法、说明使用条件、提出有前文依据的未解问题或形成进一步认识时，再用总分总。先检查中间是否讲清观点，再判断段尾是否增加认识，不为结构齐整补写重复总结。

段尾应说明具体差别、共同做法、使用条件、代价或仍未回答的问题。不仅重复论文名单，不写“各有优势”“提升了性能”充当综合，也不临时引入前文没有讨论的“表示选择”等新任务。定义段、短例证段或已经完成解释的段落不必另加总结。

总结段落和章节收束集中综合前文分论点、共同认识与仍面对的挑战，不再逐篇介绍文献或添加引用。总结需要的证据先在相应论述段中交代，新的方法、数据集或独立实验结果放回对应论述段展开。直接总结已有内容，不以“总体来看，本小节讨论了……”等篇章说明开场。

小节结束时检查各段是否已经共同回答核心问题。需要综合时，回收各段的共同认识，不只总结最后一个例子；已回答充分时，允许停在完成论述的位置。将已有证据支持的限制自然接入综合，写清感知、数据或建模条件怎样影响预测或使用，不机械追加局限清单或独立总结段。区分方法所需前提、实际观察到的失败和仍待验证的范围，不给每篇论文机械附加免责声明，不将局部失败扩大为共同失败。比较不只为证明优劣，机制差别本身也可以形成有意义的认识。

## 句子与交付

- 中文叙述正文不用分号或冒号，包括 `；`、`;`、`：`、`:`。用完整句和句号组织解释，必要时重写逻辑，不做机械标点替换。保留数学表达、URL、LaTeX 标签等技术语法中必要的符号，例如 `\label{sec:prediction}`。
- 以完整意思组织句子和自然段。能用一个自然完整的句子说清，就不拆成三四个短句，也不把连贯论述改成零碎短段或条列。尤其保持文献介绍中做法、用途和结果之间的连续关系，简洁以读者能顺畅理解为准。
- 用明确主体、动作和变化解释方法。减少抽象名词堆叠、口号与反复的“不等于”“不能保证”。必要的证据边界用具体条件表达，不为了顺畅删去事实限制。
- 比较方法时直接写明方法名称、具体做法或机制差别，不用“前者／后者”代指，也不套用“两者都……前者……后者……”及类似的先概括再逐项回指句式。例子已经说明差别时，段尾直接写共同条件、作用或局限，不再重复分述各项方法。不要只把代词换成方法名而保留重复比较的句式。
- 少用 AI 常见的制式句型，例如“不是 A，而是 B”“与其 A，不如 B”“这不代表 A，而是 B”“但 B 的合理不能代替 A 的合理”“B 并不代表 A”“A 的进一步改善，还需要考察 B 的作用”。优先直接说明具体差别、条件及后果，只在某一句型确实能让当前关系更清楚时采用，不为转折、收束或显得审慎而套用，也不通过替换近义词保留同样的空泛句式。
- 最终正文放在一个标记为 `latex` 的代码块内。按本轮授权保留或调整标题命令与段落划分，保留必要的公式、引用和交叉引用。块内只放可以进入论文的 LaTeX 正文，不放 Markdown 加粗、编辑说明、作者批注或待办提示。
- 不默认补文档类、导言区或编译文件，不以附件代替对话中的正文。用户只给正文段落时，不自行新增章节命令。
- 默认完整输出指定范围。确因长度需要分块时，按现有小节顺序连续交付 `latex` 块，保持衔接。结构冲突阻碍完整精修时明确说明受影响范围，不把仅已润色或尚未交付的内容声称为已解决。
- 代码块外仅简短说明重要调整、证据缺口或需作者判断的地方。事实不足时保留有依据的表述，将待核查事项放在块外，不在论文里伪装成确定结论。

下面只示范段首承接的表达，不预设其他章节也应按这一过程组织。

```latex
有了描述环境的状态表示，模型还需要学习机器人执行不同动作后，状态会怎样变化。
```

## 已认可参考案例

以[作者认可的完整正文与三项标注](references/approved-wm-prediction-section.md)作为解释深度、连接例子和按需收束的主要参照。涉及预测怎样参与动作选择与修正时，还可按需参考[原有规划样段](references/approved-wm-planning-paragraph.md)。学习论证组织，不迁移其技术结论，不预设其他主题的段数、例子数量或篇幅，也不新增每次使用前的样段验收、Survey 检索或校准步骤。

结构冲突的反例是，前文已比较模拟训练后的收益、退步与能力保留，后面的小节再次解释同一结果，却没有新增比较。即使后一个小节内部承接流畅，也应先指出职责重叠，比较合并与保留新增综合的安排。不能由这一反例预设所有检验小节都应取消，也不能将同一论文用于不同问题一律判为重复。

## 交付前内部检查

按以下优先级检查，属于执行本 skill 的默认工作，无需作者另行提醒或追加审核请求。发现论述问题后，在授权范围内修正并复读相关段落；前一层存在实质问题时，后一层修改不能作为精修完成的依据。检查在内部进行，不另加样段验收、写作校准或检查报告，仅向作者说明影响判断或交付的问题。
